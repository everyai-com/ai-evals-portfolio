# p09 Production Drift Monitor

## What
A nightly daemon that samples 5% of a day's production trajectories (stratified by hour or
tenant, deterministic per seed+date, optional oversampling of thumbs-down traffic), scores them
offline with pluggable scorers, persists per-day metrics, and compares today against a rolling
7-day baseline with four independent detectors:

| detector | metric | rule |
|---|---|---|
| `cusum` | success rate | Page's one-sided CUSUM, standardised by the baseline sigma: `S_t = max(0, S_{t-1} - z_t - k)`, alert when `S_t > h` |
| `zscore` | success rate | `z = (p_base - p_today) / sqrt(p_base(1-p_base)/n_today)` plus Wilson 95% CI non-overlap |
| `psi` | tool-call count and answer-length distributions | Population Stability Index with Jeffreys smoothing, minus its expected sampling noise `(k-1)(1/n_b+1/n_c)`, gated on a chi-square(k-1) tail |
| `hallucination_spike` | judge hallucination flag rate | `>= ratio x baseline`, `>= min_abs` higher, `>= min_count` flags, binomial tail `<= max_p` |

Each `Alert(severity, metric, baseline, current, evidence, sample_trajectory_ids)` carries ids of
failing trajectories so an on-call engineer can open the exact runs. Thresholds live in
`data/thresholds.yaml`.

## Why
Users complain days after quality decays. A 5% nightly sample with paired-to-baseline statistics
catches a success-rate drop of ~10 points with 50 trajectories per night, and the four detectors
cover different failure shapes: step-change (CUSUM, z), behavioural shift without a success
change yet (PSI on tool calls / verbosity), and unsupported claims (judge spike).

## How to run
```bash
# 14 synthetic days, quality decays from day 10 (2026-10-11), daemon runs day by day
.venv/bin/python -m projects.p09_drift_monitor.cli simulate --days 14 --drift-day 10 --rate 0.05 --out state/
# one real day against the stored baseline (exit 1 if a critical alert fires)
.venv/bin/python -m projects.p09_drift_monitor.cli run-once --traffic projects/p09_drift_monitor/data/sample_day_2026-10-15.jsonl --date 2026-10-15 --rate 0.5 --state state/
.venv/bin/python -m projects.p09_drift_monitor.cli report --state state/
.venv/bin/pytest projects/p09_drift_monitor -q
```
`--stratify tenant` and `--feedback-weight 5` change the sampler; `--config` and `--schema` point
at the YAML thresholds and tool schema. `evalkit drift ...` is the same CLI.

Library use:
```python
from projects.p09_drift_monitor import Daemon, TrafficSampler, OfflineEvaluator, RuleScorer, JudgeScorer, LengthScorer, DriftDetector, StdoutSink, WebhookSink
daemon = Daemon(traffic_source=lambda date: load_day(date), sampler=TrafficSampler(0.05, seed=0),
                evaluator=OfflineEvaluator([RuleScorer(schema), JudgeScorer(judge_client), LengthScorer()]),
                detector=DriftDetector(thresholds), state_dir="state/", sinks=[StdoutSink(), WebhookSink(url)])
metrics, alerts = daemon.run_once("2026-10-15")   # or daemon.run_loop(interval_s=86400)
```

## Design notes
* **Sampling** is a deterministic weighted reservoir (Efraimidis-Spirakis A-Res): each row gets
  `u = sha256(seed:date:task_id)` and key `u^(1/w)`; the top-k keys per stratum are kept, with
  k allocated across strata by largest remainder so the total is exactly `round(rate * n)`.
  `feedback_weight > 1` raises `w` for thumbs-down rows, oversampling the traffic users already
  complained about without changing the sample size.
* **Scorers** implement `score(Trajectory) -> dict`. `RuleScorer` checks tool calls against a
  required-args schema, non-empty final answer and absence of error steps (`success` = all
  three). `JudgeScorer` asks an `LLMClient` for `OK` / `HALLUCINATION`; offline it is a `MockLLM`
  scripted on the synthetic hallucination markers, and `EVALKIT_LLM=anthropic` swaps in the real
  model. `LengthScorer` feeds the PSI distributions.
* **Baseline** is the last `baseline_window_days` days with data before today; fewer than
  `min_baseline_days` means no alerts (cold start is silent, not noisy). The baseline is a plain
  rolling window, so after a sustained drift the baseline itself degrades and CUSUM/z alerts fade
  (visible on 2026-10-14 above); PSI and the spike rule keep firing because they compare shapes.
* **Why the extra statistics on PSI and spikes.** With 50 samples a night, raw PSI over five
  bins averages ~0.1 under *no* drift and a 2% base hallucination rate makes 4 flags look like a
  4x spike. Subtracting the expected PSI noise, gating on a chi-square tail, and requiring a
  binomial tail `<= 0.005` keeps stable days silent across seeds while drift still fires on day
  one. `chi2_sf` and `binom_sf` are implemented in `core.py` (no scipy).
* **State** is two JSONL files: `metrics.jsonl` (one `DayMetrics` per date, re-running a date
  replaces it) and `alerts.jsonl`. `WebhookSink` POSTs JSON via `urllib` with an injectable
  opener; sink failures are logged, never raised.
