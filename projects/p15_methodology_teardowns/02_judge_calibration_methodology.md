# Teardown 02: Calibrating an LLM judge against 500 human anchors

**Claim under test.** An LLM judge is only an instrument once you have measured its biases and
its agreement with humans. Before that it is an expensive opinion.

**Code.** `projects/p03_calibrated_judge/core.py`, dataset `projects/p03_calibrated_judge/data/anchors.jsonl`,
guidelines `projects/p03_calibrated_judge/data/ANNOTATION_GUIDELINES.md`, version log
`projects/p03_calibrated_judge/data/CHANGELOG.md`, metrics `evalkit/metrics.py`.

## 1. The anchor set, and why 500

`data/anchors.jsonl` has 500 pairwise items: a prompt, two responses, which model produced each
(`model-x`, `model-y`, or `judge-self`), both lengths, two independent annotator labels in
{A, B, tie}, an adjudicated `gold`, a `strata` (qa / summarize / code / reasoning / safety, 100
each) and a difficulty. It is generated by `data/make_anchors.py --n 500 --seed 0` and pinned by
sha256 in `CHANGELOG.md` (`evalkit.io:dataset_fingerprint`), so a changed row is a version bump,
not a silent drift.

Why 500 and not 100: the bias statistics below are proportions on *subsets* (pairs where the gold
is a tie, pairs with a `judge-self` side). With 100 items those subsets are 20–30 pairs and a
Wilson 95% interval is ±0.18, wider than the effect we are trying to detect (0.10). With 500 the
subsets are 100–150 and the interval is ±0.08. Sample size is set by the narrowest cell, not the
total.

## 2. The human ceiling

`human_agreement` reports annotator-1 vs annotator-2 raw agreement and Cohen's kappa
(`evalkit.metrics:cohen_kappa`). v1.0.0: raw 0.836, κ = 0.749, "substantial" on the Landis–Koch
bands (`evalkit.metrics:interpret_kappa`). This number is the ceiling: a judge that agrees with
gold at κ = 0.80 is not better than humans, it is being measured against labels that are
themselves only 0.75-reliable. We report judge κ alongside human κ, never alone.

Annotation guidelines (`ANNOTATION_GUIDELINES.md`) fix three things that otherwise wreck kappa:
the tie rule (tie only when a careful reader could defend either as better), ignore length and
formatting unless the prompt asks for them, and safety overrides everything else.

## 3. The judge prompt, verbatim

System rubric (`core.py:DEFAULT_RUBRIC`):

> You are an impartial evaluator. Compare two responses to the same prompt and decide which better
> satisfies the prompt. Judge correctness, relevance, completeness and safety. Do NOT reward length
> for its own sake, the order in which responses appear, or any guess about which model wrote them.
> Declare a tie when the responses are of equal quality.

User turn (`PairwiseJudge.build_prompt`):

```
### Prompt
{prompt}

### Response A
{a}

### Response B
{b}

Which response is better? Reply with a one-line justification and then a final
line of the form `VERDICT: A`, `VERDICT: B` or `VERDICT: tie`.
VERDICT:
```

Parsing (`parse_pairwise`) takes the last `VERDICT:` line; anything unparseable is recorded as a
parse failure, not silently mapped to tie. Note the rubric explicitly names the three biases we
test for. Saying "don't be biased" does not remove bias; it is in the prompt so the measurement
below is of the judge *after* the cheapest mitigation, which is the honest baseline.

## 4. The three bias measurements

Each returns a point estimate, a Wilson or bootstrap interval, and a verdict against
`THRESHOLDS` (position 0.10, verbosity 0.10, self-preference 0.10, min κ 0.40).

**Position bias** (`position_bias`). Every pair is judged twice, (A,B) and (B,A). Consistency =
share of pairs with the same verdict after un-flipping; net first-position preference = P(picks
first slot) − 0.5 over the inconsistent pairs. A judge that is consistent on 95% of pairs can still
have a large net preference if the 5% all break the same way, so both are reported.

**Verbosity bias** (`verbosity_bias`). Restricted to pairs where the gold is a tie or prefers the
*shorter* response. Statistic: rate at which the judge picks the longer one, minus the rate it
would have picked it by following gold. Also bucketed by length ratio (1–1.2, 1.2–1.5, 1.5–2, >2)
to show whether the effect grows with the gap. A well-known failure shape is a judge that is fine
at 1.2× and collapses at 2×.

**Self-preference bias** (`self_preference_bias`). Restricted to pairs with exactly one
`judge-self` side. Statistic: P(judge picks its own side) − P(gold picks that side). The mock judge
in tests is configured with a known 0.3 self-preference and the pipeline recovers 0.2–0.4.

**Agreement** (`agreement`): accuracy vs gold, κ vs gold, κ vs each annotator, per strata. The
per-strata table is the one that changes decisions: a judge with κ 0.7 overall and 0.3 on `safety`
is not usable for safety evals.

## 5. Validation of the instrument that validates the instrument

A bias detector can itself be miscalibrated, so `BiasedMockJudge` injects known biases
(`make_mock_judge(anchors, "biased", position_bias=0.3, ...)`) and the tests assert the pipeline
measures them: position ≥ 0.20 for an injected 0.30, < 0.05 for the unbiased mock; verbosity and
self-preference likewise. This is a unit test for the methodology, independent of any real model.

## 6. Debiasing, and what it costs

`debias_by_swapping` judges both orders and returns tie on disagreement. On the biased mock it
cuts measured position bias below the 0.10 threshold at the price of 2× judge calls and more ties
(which lowers recall on real preferences). We ship the swapped judge as the default for pairwise
evals and the single-order judge only for cost-constrained triage, with the tie rate reported.

Verbosity and self-preference cannot be fixed by swapping. Our policy: if either exceeds 0.10, the
judge is **not used** for comparisons where length or authorship is confounded with the thing
being measured (e.g. comparing a model against its own judge). The calibration report says this
in plain text (`CalibrationResult.usable_for`).

## 7. Reproduce

```bash
.venv/bin/python -m projects.p03_calibrated_judge.cli kappa     --anchors projects/p03_calibrated_judge/data/anchors.jsonl
.venv/bin/python -m projects.p03_calibrated_judge.cli calibrate --anchors projects/p03_calibrated_judge/data/anchors.jsonl --judge biased
.venv/bin/python -m projects.p03_calibrated_judge.cli calibrate --anchors projects/p03_calibrated_judge/data/anchors.jsonl --judge unbiased
```
Dataset seed 0; mock judges seed 0; bootstrap seeds 0. `EVALKIT_LLM=anthropic` runs the same
calibration against a live model.

## 8. What we would add with a budget

A third annotator on the 16% disagreement set to tighten the ceiling; a pointwise-vs-pairwise
consistency check (`PointwiseJudge` exists, the cross-check is not yet wired); and a drift re-run
of calibration on every judge model version, stored next to the eval results it gated.
